# Job Market Intelligence

A end-to-end data engineering and analytics platform for the Indian technology job market. The platform ingests, cleans, and merges multiple heterogeneous job datasets into a unified PostgreSQL database, then surfaces insights through SQL analytical queries, Python-generated charts, an automated Excel report, and a Power BI dashboard.

---

## Overview

The platform aggregates data from three source datasets spanning salary benchmarks, fresher hiring pipelines, and global AI/ML job market insights. It normalises job titles across more than 60 role variations, maps them to canonical sector labels, and loads the result into a relational schema optimised for analytical querying. The entire workflow is scripted end-to-end with no manual data transformation required.

**Key capabilities**

- Multi-source ETL pipeline merging India salary data, fresher hiring records, and AI/ML market insights
- Canonical role normalisation across 60+ title variations (Data Analyst, ML Engineer, DevOps, etc.)
- PostgreSQL star schema with dimension and fact tables plus 10 analytical SQL queries
- Automated Excel report with pivot tables and embedded bar charts (openpyxl)
- Fresher hiring analysis with six matplotlib/seaborn visualisations
- Power BI dashboard layer for interactive filtering and stakeholder reporting

## Datasets

| ID | File | Description | Rows (approx.) |
|----|------|-------------|----------------|
| DS1 | `job_market_india.csv` | India job listings with monthly salary in INR | ~5,000 |
| DS2 | `fresher_hiring_india_dataset.csv` | End-to-end fresher application pipeline with hiring outcomes | ~10,000 |
| DS3 | `ai_job_market_insights.csv` | Global AI/ML role insights (salary in USD, skills, automation risk) | ~500 |
| DS4 | `postings.csv` | LinkedIn US postings — **skipped**, zero India rows after filtering |  |

DS3 salaries are converted to INR at an approximate rate of 83.5 USD/INR. DS3 records are assigned to Indian tech hub cities for geographic consistency with DS1 and DS2.

## Pipeline

| Step | Script / Artifact | Description |
|------|-------------------|-------------|
| 1 | `scripts/clean_data.py` | Loads DS1, DS2, DS3; normalises roles, salaries, and skills; merges into `job_market_combined.csv` |
| 2 | `scripts/load_to_postgres.py` | Reads the processed CSV and upserts records into `job_listings` and `fresher_applications` |

| 3 | `notebooks/02_hiring_analysis.ipynb` | Notebook version of fresher hiring analysis |

| 4 | `scripts/generate_excel.py` | Writes a formatted Excel workbook with a KPI dashboard, pivot tables, and embedded bar charts |
| 5 | `powerbi/dashboard.pbix` | Power BI file connecting to PostgreSQL for interactive stakeholder reporting |

## Database Schema

The PostgreSQL schema follows a lightweight star model.

**Dimension tables**

| Table | Key columns | Purpose |
|-------|-------------|---------|
| `dim_city` | `city_id`, `city`, `state`, `locality` | Canonical city reference |
| `dim_role` | `role_id`, `job_role`, `sector` | Canonical role and sector reference |

**Fact tables**

| Table | Key columns | Source |
|-------|-------------|--------|
| `job_listings` | `listing_id`, `job_role`, `city`, `salary_inr`, `source` | DS1 + DS3 (`salary_ds`, `ai_market_ds`) |
| `fresher_applications` | `app_id`, candidate profile, `hiring_stage`, `hired`, `platform`, `skills` | DS2 (`fresher_ds`) |

Indexes are created on `city`, `job_role`, `salary_inr`, `platform`, `hired`, `sector`, `graduation_year`, and `hiring_stage` to support the analytical query workload.

## Analytical Queries

`sql/analysis_queries.sql` contains ten production-ready queries:

| Query | Question answered |
|-------|-------------------|
| Q1 | Which Indian cities offer the highest average salaries? |
| Q2 | Which job roles command the highest salaries? |
| Q3 | Which job platforms give freshers the best hire rate? |
| Q4 | Does CGPA band significantly affect hiring outcomes? |
| Q5 | Does prior internship experience improve hire rate? |
| Q6 | Which skills appear most frequently among hired candidates? |
| Q7 | How do fresher offered salaries compare to market rates by role? |
| Q8 | Where in the hiring funnel do most candidates drop off? |
| Q9 | Which sectors offer the most remote-friendly positions? |
| Q10 | Does applying with a referral improve hire rate and response time? |

## Quick Start

**Prerequisites:** Python 3.10+, PostgreSQL 14+, Git.

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/job-market-intelligence.git
cd job-market-intelligence

# 2. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

# 3. Install dependencies
pip install -r requirements.txt

# 4. Configure environment variables
copy .env.example .env
# Open .env and set DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD

# 5. Place raw CSVs in data/raw/
#    job_market_india.csv
#    fresher_hiring_india_dataset.csv
#    ai_job_market_insights.csv  (optional)

# 6. Create the PostgreSQL schema
psql -U postgres -d job_market -f sql/schema.sql

# 7. Run the full pipeline
python scripts/clean_data.py
python scripts/load_to_postgres.py
python scripts/hiring_analysis.py
python scripts/generate_excel.py
```

## Role Normalisation

`clean_data.py` maps 60+ raw job title variants to a set of canonical role names using substring matching. Examples:

| Raw title variants | Canonical role |
|--------------------|---------------|
| `ml engineer`, `machine learning`, `deep learning` | `ML Engineer` |
| `generative ai`, `gen ai`, `llm` | `Generative AI Engineer` |
| `software engineer`, `software developer`, `python developer` | `Software Engineer` |
| `devops`, `site reliability` | `DevOps Engineer` |
| `full stack`, `fullstack` | `Full Stack Developer` |

Roles in the Data/AI/ML cluster are assigned the `Data/AI/ML` sector label; all others default to `IT/Software`.

## Security Notes

- `.env` is excluded from version control via `.gitignore`. Never commit database credentials.
- Raw CSV files in `data/raw/` are also excluded. Distribute datasets separately through a secure channel or a private data store.
- Use a dedicated PostgreSQL role with least-privilege access (SELECT, INSERT, UPDATE on the target tables only) for production ingestion.
